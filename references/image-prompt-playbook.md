# Image 视觉设计提示词手册

## 通用原则

向 Image 模型提供明确的业务背景、用户任务、参考截图、视口比例、视觉方向、必须保留的内容和禁止项。避免只说“做得高级一点”“更有设计感”。

Image 生成后必须经过 [design-critique.md](design-critique.md) 的独立视角评审；不要把第一张图直接交给开发实现。

提示词需要输入真实内容语义：零值、缺失、未知、加载失败、长文字和窄视口等容易使布局失效的条件。不能默认只有理想样例数据。

## A. 已有页面重设计模板

\`\`\`text
请基于我提供的当前页面截图，重新设计一个可实际落地的高保真 Web UI。

业务目标：{本次要解决的问题}
目标用户：{角色}
核心任务：{用户在页面上要完成什么}
必须保留：{功能入口、字段、数据、业务流程}
不可改变：{API、路由、权限、业务规则等}
目标视口：{例如 1440x900}
品牌与产品定位：{已知品牌规范、产品气质、用户预期}
内容密度：{低/中/高，说明原因}

设计要求：
- 保留必要业务信息和功能，不擅自删除入口。
- 先建立明确的信息架构和视觉焦点。
- 有产品识别度，避免直接套用通用后台模板。
- 控制卡片数量、渐变、阴影和背景装饰，避免堆叠。
- 让字体层级、间距、网格和色彩比例形成统一系统。
- 需要图标或背景时，设计真实可拆分的视觉资产，不要用 Emoji 或字符代替。
- 不生成假浏览器边框、假 Logo、乱码文字、水印或整页截图式背景。
- 页面必须能由 HTML/CSS/组件实现，交互控件形态清楚。
- 输出完整页面构图；复杂页面按需提供关键状态和移动端方案。
- 对最容易造成布局失败的一个边界状态进行单独构图或说明，避免正常态好看、异常态崩溃。
\`\`\`

## B. 从零设计模板

\`\`\`text
请根据以下业务需求设计一个高保真 Web UI 概念稿。

产品/模块：{名称}
用户角色：{角色}
业务目标：{目标}
核心任务：{任务列表}
页面内容：{信息架构}
主要操作：{操作}
数据密度：{低/中/高及示例}
终端与视口：{PC / H5 / 移动端}
品牌约束：{颜色、Logo、行业属性}
工程约束：{框架、组件库、现有设计系统}

请先组织信息架构，再形成有辨识度的视觉方向。
优先保证业务流程清晰、信息层级明确、视觉精致、组件统一和响应式可实现。
为必要的图标、插画、背景图和空状态建立统一风格，不要用字符或 Emoji 代替图标。
不要在生成图里写大量真实文案或伪造业务数据。
设计除正常态外至少一个压力状态，并说明如何保持信息层级与真实单位。
\`\`\`

## C. 独立评审与三图对照补充原则

评审者应从需求、真实数据状态和页面截图出发，不继承设计生成者的自评分。必须指出可以定位的区域、用户影响和修订动作。通过评审的设计稿要保留 Target 版本，以便后续与真实浏览器 After 截图比较。没有独立审查 Agent 时应标明单 Agent 反向审查。

## D. 设计评审/迭代模板

\`\`\`text
请不要直接接受这张设计稿。请作为独立的高级 UI/UX 设计评审者进行批判性检查。

检查：
1. 是否准确满足需求并保留核心任务？
2. 信息架构和阅读/操作路径是否自然？
3. 视觉焦点、层级、密度和留白是否合理？
4. 是否有产品识别度，还是通用模板换色？
5. 排版、色彩、组件和视觉资产是否统一？
6. 是否有无意义的卡片、渐变、阴影、背景图或装饰？
7. 交互状态、移动端和可访问性是否考虑？
8. 是否能用当前技术栈真实实现？

请指出具体问题、影响和可执行修订动作，再生成修订后的设计稿。
不要只给“更高级、更现代”这类空泛建议。
\`\`\`

## E. 生成一组统一图标模板

\`\`\`text
生成一套用于同一个产品的图标资产。
图标主题：{功能列表}
风格：{线性/面性/双色/轻 3D，选定一种主风格}
统一要求：相同画布尺寸、视觉重心、线条粗细、圆角、透视、光照和主辅色。
每个图标单独、完整、居中，四周留白一致；透明背景优先；不要文字、字母、数字、水印、边框或多余装饰。
输出应便于裁切成独立资产，并在实际显示尺寸检查清晰度。
\`\`\`

## F. 生成背景图模板

\`\`\`text
为 {页面/模块} 生成可用于真实产品的背景视觉资产。
画布比例：{16:9 / 3:1 / 4:5 等}
主题：{业务主题}
主体位置：{左/右/居中/边缘}
文字安全区：{明确区域，保持低细节和足够对比}
色彩：{品牌色与辅助色}
风格：{抽象科技/柔和纹理/行业场景/轻插画}
禁止：文字、Logo、按钮、假 UI、二维码、水印和过强高频细节。
考虑 PC 和移动端裁切；若构图无法兼容，应分别生成。
\`\`\`

## G. 生成后检查

- 构图和内容是否符合需求？
- 是否包含错误文字、假 Logo、水印或多余控件？
- 是否匹配目标视口并可由真实组件实现？
- 透明背景、裁切和留白是否合格？
- 同一套资产风格是否一致？
- 是否已通过设计评审并保存到项目资产目录？
- 是否在真实数据/缺失值/窄屏等高风险条件下仍成立？
- 目标稿版本、视口和需在浏览器验证的假设是否记录？
