# 交互成本与操作减负

## 目标

降低用户完成任务所需的填写、点击、等待、记忆和判断成本，同时保留功能可发现性、业务正确性、用户控制权和安全性。

**减少控件数量不等于减少操作成本；隐藏核心功能、增加猜测或造成误操作，都不是优化。**

## 1. 先画完整任务路径

选择本轮最重要的 1–3 个用户任务，从入口到完成记录：
- 入口与用户当前上下文。
- 每一步需要的点击、输入、选择和决策。
- 需要等待的接口/异步动作。
- 重复填写、跨页面跳转和重复确认。
- 容易出错、失败后无法恢复的环节。
- 完成后的反馈和持久化行为。

区分首次使用、熟练用户和异常/恢复路径，不只优化理想的熟练用户路径。

## 2. 字段分类

| 字段类型 | 推荐策略 | 约束 |
|---|---|---|
| 必须且无法可靠推导 | 保留为明确输入 | 说明格式和校验规则 |
| 可从可信上下文获得 | 预填并允许修改 | 说明来源，不覆盖用户编辑 |
| 可稍后补充 | 设为选填或渐进展开 | 不隐藏提交必需条件 |
| 已有/常用内容 | 选择、复用、模板化 | 确认内容仍然适用 |
| 低频高级配置 | 收纳到可发现的次级入口 | 不能藏掉核心任务 |
| 敏感/高风险字段 | 明确展示和必要确认 | 不擅自推断或自动提交 |

默认值必须来自可信业务规则或明确上下文；未知值不能自动变成零、空字符串或任意默认项。

## 3. 动作与路径分类

- 可安全撤销的低风险动作：可考虑一步执行、明确成功反馈和撤销。
- 不可逆或高风险动作：保留确认、权限和必要二次校验。
- 重复动作：考虑批量处理、最近使用、模板或智能复用。
- 冗长流程：考虑合理分组、上下文保持、渐进披露和就地编辑。
- 等待过程：提供真实 Loading/Progress，防止重复提交。
- 失败过程：保留草稿和用户已输入内容，提供可重试路径。
- 自动预填/识别：提供修改入口，异步结果不得覆盖用户已编辑内容。

## 4. 操作减负的安全边界

- 不擅自改变用户选择的日期、数量、对象、目标或业务范围。
- 不因减少点击而移除关键功能、权限检查、审计记录或合规确认。
- 不自动触发付费调用、上传、外部消息、数据采集或不可逆操作，除非已获明确授权。
- 不把“自动化”当作默认正确；必须允许用户查看、纠正和取消。
- 防止重复提交，确保保存/重试行为与现有后端约束一致。
- 重要操作应有明确的成功、失败和结果持久化反馈。

## 5. 衡量指标

优化前后按实际任务比较：
- 必填字段数与手工输入项。
- 点击/选择/页面跳转数量。
- 需要用户记忆或判断的事项。
- 任务完成时间（如可测）。
- 错误率、放弃率、返工次数和撤销次数。
- 功能发现率与用户是否能理解下一步。

不能只统计点击减少；如果点击减少但错误率上升或用户找不到功能，不算成功。没有真实埋点/观察数据时，明确标注为流程分析估计，不伪造数据。
