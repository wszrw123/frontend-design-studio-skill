# 三图对照与真实视觉差异闭环

## 目标

防止“设计稿很好看，真实界面只做到勉强排齐”，以及“实际上没截图却宣称已经验收”。

## 三类证据

- **Before**：旧页面真实截图；新建页面可注明没有基线。
- **Target**：经过设计门禁的高保真 Image 目标设计稿，标记版本和适用视口。
- **After**：真实项目运行、关键资源加载完成、关闭调试覆盖层后的浏览器截图。

## 可比性

比较前记录：视口尺寸、DPR/缩放、滚动位置、主题/语言、业务数据状态、字体/图片加载状态、用户角色、截图采样时间。无法对齐时明确写“仅结构性对比”，不得虚构精准像素差异百分比。

关闭 DevTools 元素高亮、无障碍检查器覆盖层、布局网格和临时调试浮层。不要把它们误当成产品 UI。

## 分区检查

对每个区域比较：
1. 内容完整性、业务操作入口、信息层级。
2. 布局、对齐、间距、字体、对比度。
3. 组件、图标、背景与插画的品质和裁切。
4. 真实零值、缺失、加载与长文本下的响应。
5. 弹窗、Tab、滚动、底部导航、表单等交互状态。
6. 公共组件影响的其他页面及各主要变体。

## 差异归因

- **设计缺陷**：Target 方案本身业务表达不清、层级错误或不可实现；先改设计。
- **工程偏差**：Target 合格，但代码与设计稿不同；改实现。
- **内容状态差异**：真实数据或状态与生成参考不一致；统一语义后重测。
- **环境噪声**：动态时钟、检查器、未加载字体、截图尺寸不同；先消除噪声。
- **关联回归**：公共组件改动导致其他页面异常；扩大回归范围。

## 工具与方法边界

如果有真正的截图比较工具，可生成像素差、叠加图或差异框，但像素相似度不等于可用性，且数据状态不同的图不能直接得出量化结论。不得编造对比数值或声称运行未使用的工具。

## 结果与证据

每条重大差异记录区域、观察到的问题、影响、根因、建议修复、实际修复和复测截图路径。重大问题未解决或缺乏真实截图时，必须标记 PARTIAL / BLOCKED，不得声称视觉 PASS。
