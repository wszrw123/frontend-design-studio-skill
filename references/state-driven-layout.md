# 数据状态驱动的布局与信息层级

## 目标

设计必须在真实内容条件下成立，而不是只在漂亮的示例数字与短文案下成立。业务重要性决定内容顺序和信息架构；数据状态与内容密度决定当前表现强度、排布和反馈。

## 先确认数据契约

记录每个关键字段的名称、单位、周期、格式、是否允许为零、空值与缺失值语义、更新时效和权限要求。明确“真实零值”和“暂无数据”是否不同，不能靠猜测决定显示。

## 状态矩阵

| 状态 | 推荐表达 | 禁止的做法 |
|---|---|---|
| 正常 | 保留真实值、单位、周期、上下文 | 为装饰伪造趋势 |
| 真实零值 | 显示 0 和相关业务语义 | 当成错误或缺失 |
| 未知/缺失 | 明确“暂无数据”与必要原因 | 直接填 0 |
| 加载中 | 稳定骨架和进度反馈 | 长时间伪造已完成数据 |
| 失败 | 可读错误与适用的重试入口 | 静默空白 |
| 部分可用 | 区分可用字段与不可用字段 | 整体伪装为完整 |
| 数据过期 | 标注更新时间、提供刷新机会 | 让旧数据看似实时 |
| 无权限 | 合理权限反馈，不泄露敏感数据 | 假装为普通空数据 |
| 极端内容 | 保留可读性、合理截断与完整访问路径 | 缩小到难读或挤压按钮 |

## 视觉层级与布局

- 不允许不可用的巨大占位符抢占首要视觉中心；同时不能偷偷改变核心业务重要性。
- 在真实数据不足以比较时，不强制出现分布图、柱状图、比例或进度条；选择语义准确的状态。
- 多列组件必须经过真实文案长度测试；窄屏出现挤压、逐字换行时重新分栏或调整信息优先级，而不是一味缩字号。
- 同一组件在 0/空/加载/异常/正常和极端数值下保持布局稳定，不应因数字位数变化覆盖其他操作。
- 选择表格、列表、卡片、图表时先看用户需要比较、浏览还是操作，再看数据密度与视口，而不是为了设计稿好看套固定模式。

## 压力状态

至少选择正常状态和一个最可能造成严重布局问题的状态进行设计与验收；根据业务再加入加载/失败、无权限、长文案和极端值。不得为“通过验收”修改生产数据。
