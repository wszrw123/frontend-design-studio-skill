# 视觉语言提取与延伸

## 目标

在重设计前识别产品已经建立的视觉资产和用户认可的界面区域。优先延伸有效的设计语言，修复不一致或低质量部分，而不是每轮任务都从零换风格。

## 1. 证据来源

按可信度使用：
1. 用户明确指出满意、希望保留或作为参考的页面/区域。
2. 当前产品已稳定使用的品牌规范、Design Tokens 和公共组件。
3. 多个页面中一致且表现良好的视觉模式。
4. 单页中可观察到的有效视觉处理（需要确认是否是偶然样式）。

不能仅凭“当前存在”就认定用户满意。把发现分成：
- 已确认保留：用户明确认可或指定。
- 值得延伸：在多个页面中一致、有效且符合品牌。
- 待验证：只有局部证据，可能是历史遗留。
- 应修复：明显影响阅读、操作、品牌一致性或可访问性。

## 2. 提取维度

| 维度 | 记录内容 |
|---|---|
| 品牌与情绪 | 产品定位、品牌色、视觉语气、行业属性 |
| 色彩 | 主色/辅助色/状态色/中性色及使用比例 |
| 字体与层级 | 字体、字号、字重、行高、数字和标签样式 |
| 布局与节奏 | 栅格、容器、留白、密度、对齐和页面节奏 |
| 表面语言 | 背景、卡片、边框、圆角、阴影、材质 |
| 图标语言 | 线条/填充、笔触、视觉重心、尺寸与状态 |
| 图像语言 | 摄影/插画/3D/抽象纹理、光照、构图和裁切 |
| 交互语言 | Hover、Active、Focus、反馈、动效和过渡 |
| 内容表达 | 标题语气、辅助说明、单位、空状态和错误反馈 |

## 3. 延伸原则

- 保留已确认满意的部分，除非用户明确要求改变或它存在严重可用性/安全问题。
- 对满意区域优先做兼容性、间距和状态补齐，不要随意换色、换图标或重构布局。
- 把可复用规律提取为 Token、组件或页面模式；不要复制单页临时 CSS。
- 允许不同业务页面有自己的信息结构和密度，但共享品牌、字体、颜色、图标与交互基础。
- 不把某一张参考图中的偶然装饰误判为全站设计规范。
- 若旧视觉语言本身不一致，先提出统一策略，再分阶段迁移，避免一次性大爆炸式换肤。
