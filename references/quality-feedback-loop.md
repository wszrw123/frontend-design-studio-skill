# 前端设计质量反馈闭环

## 核心目的

不是只修复当次页面，而是提升下一次设计成功率：当发现重复错误时，优先改变设计/工程环境，让后续 Agent 更容易发现或无法重复相同问题。

## 问题分类

1. 需求理解问题：未保留重要功能、业务语义理解错误。
2. 视觉方向问题：模板化、缺乏产品个性、装饰挤占业务内容。
3. Image 设计问题：初稿不可实现、内容分布错误、素材不统一。
4. 设计评审问题：没有对照证据，给出空泛好评或直接放行。
5. 数据状态问题：缺失/零值混淆、长文本塌陷、虚假趋势图。
6. 工程实现问题：与目标设计不一致、公共组件不复用、CSS 覆盖冲突。
7. 验收问题：只看首屏或单一视口、混入调试覆盖层、未复测。
8. 回归问题：改一个公共组件损坏多个引用页面。

## 消除错误的优先级

1. 明确并校验上游的需求和数据契约。
2. 修改设计评审门禁或提示词，让错误在编码前被发现。
3. 改进可复用组件 API、Design Tokens、资产规范。
4. 添加可自动执行的测试或截图验证（仅当工具真实可用）。
5. 最后才添加页面级补丁；不能把页面级特殊处理升级为通用规定。

## 通用性边界

通用 Skill 不写客户名、内部地址、业务字段、特定页面布局或特殊品牌偏好。规则要表述为“何时触发、如何检查、什么算通过”，并说明例外，不制造僵化的审美模板。

不得宣称工具、测试、子 Agent 或后台持续任务已完成，除非有真实执行结果。
