# 使用示例

## 已有页面改造

> 使用 frontend-design-studio。先理解本次优化目标，再获取当前页面真实截图并分析源码。根据产品定位和业务任务定义视觉方向，调用 Image 生成完整高保真设计稿。不要直接接受第一稿，先按设计评审量表检查业务适配、信息层级、视觉个性、排版、组件、资产、状态、响应式和可访问性；存在关键问题时继续迭代设计稿。通过评审后再拆解公共组件和视觉资产，实施代码并完成真实浏览器验收。

## 从零设计

> 使用 frontend-design-studio。根据业务需求先整理用户任务和页面信息架构，再定义视觉方向，调用 Image 生成高保真页面方案。独立评审并修订设计稿后，拆解 Design Tokens、公共组件、页面模式和视觉资产，按当前项目技术栈实现，并完成 PC/移动端真实页面验收。

## 公共组件升级

> 使用 frontend-design-studio。先检索该组件所有引用页面和现有变体，判断是否应升级已有公共组件。通过 Image 设计目标样式，并在编码前评审组件视觉、状态、响应式和工程可行性；实施后逐一检查主要引用页面，避免只在当前页面通过。

## 设计质量复盘

> 使用 frontend-design-studio。请独立评审当前真实页面，不要只给笼统的审美评价。按需求、信息架构、层级、品牌识别、排版、组件、资产、交互、响应式、可访问性和工程实现逐项指出问题，提供证据、严重程度和可执行改进动作。不要绑定或假设任何特定业务系统。

## 继承满意的视觉语言

> 使用 frontend-design-studio。先检查我明确认可的页面/区域和当前项目设计系统，提取颜色、字体、图标、图像、间距和组件语言，区分必须保留、可延伸、待验证和需要修复的部分。不要为了重新设计而推翻满意区域，将有效语言延伸到本轮范围内的相关页面。

## 优化用户操作路径

> 使用 frontend-design-studio。先选择一个高频任务，从入口到完成记录字段、输入、点击、等待、决策和失败恢复。区分必须输入、可可靠预填、可选、可复用和低频信息，提出减少操作成本的方案；不得隐藏核心功能、改变用户选择或跳过权限/审计。实现后实测保存、修改、取消、撤销/重试及持久化，并对比优化前后任务成本。

## 视觉资产成套生成

> 使用 frontend-design-studio。先盘点项目资产，按品牌氛围、真实用户内容、功能入口、操作图标和空状态等职责确定素材需求。没有合适可复用资产时调用 Image 成套生成，统一风格、透明背景、光照、画布和留白；检查边缘、裁切、小尺寸表现和文件体积，保留源文件并登记资产清单。

## 范围受控实施

> 使用 frontend-design-studio。按我明确授权的范围执行：如果只要求分析，不修改代码；如果要求实施，直接完成授权范围内可回滚的改动。不要擅自扩大到全站重构、技术栈迁移、部署或付费外部调用；保留已有满意区域并报告未覆盖风险。
